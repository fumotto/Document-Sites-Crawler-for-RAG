# Refactoring

目的は

「動作を変えずに品質を向上させること」

## 優先順位

1. 可読性
2. 保守性
3. テスト容易性
4. パフォーマンス

## Refactoring Checklist

- 重複コード
- 長い関数
- 長いクラス
- ネスト
- 命名
- 責務分離

## SOLID

改善可能なら

- Single Responsibility
- Dependency Inversion

を検討する。

## Before Refactoring

変更前に

- 問題点
- 改善方法
- 期待効果

を説明する。

## After Refactoring

変更内容を要約する。

動作変更がある場合は必ず報告する。
