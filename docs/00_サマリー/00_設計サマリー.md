## 1. システム概要

Webサイト上のドキュメントを収集・整形し、NotebookLM（および一般のRAG用途）へアップロードしやすいMarkdownファイル群を生成するツール。Supabase Docsに限らずReact/Next.js/Cloudflare/Stripe/AWS等、一般的なドキュメントサイト全般を対象とする汎用ツール。Docker Composeのみで、Windows環境でも`docker compose up`だけで実行できることを目標とする。SPA（クライアントサイドレンダリングのみ）は対象外。
[出典: 02_基本設計書 1節, 01_要件定義書 1-2節]

### 全体アーキテクチャ

```mermaid
CLI → Orchestrator → ConfigLoader / CrawlerService / BuilderService / ArchiveService
CrawlerService -- 読み書き --> cache/{site}/
BuilderService -- 読み込み --> cache/{site}/ -- 書き込み --> output/{site}/
ArchiveService -- 読み込み --> output/{site}/ -- 書き込み --> archives/{site}/
Orchestrator -- 出力 --> logs/crawler.log
```

### ディレクトリ責務

| ディレクトリ | 責務                             |
| ------------ | -------------------------------- |
| `src`        | アプリケーションソースコード     |
| `cache`      | 差分更新に利用する永続キャッシュ |

| `archives`   | ZIP成果物の履歴保存              |
| `logs`       | ログ出力                         |
| `tests`      | テストコード                     |

### サイト識別子の生成ルール

URLから機械的・再現可能に生成する（`03_ディレクトリ構成`）：

1. スキーム（`https://`等）を除去
2. ホスト名・パスを含め全て小文字化
3. 英数字以外（`/` `.` `:` `-`等）を`_`に置換
4. `_`連続を1文字へ圧縮
5. 先頭・末尾の`_`を除去

末尾スラッシュ有無は同一識別子になる（**仕様**であり衝突ではない）。

| URL                           | サイト識別子                    |
| ----------------------------- | ------------------------------- |
| `https://supabase.com/docs/`  | `supabase_com_docs`             |
| `https://react.dev`           | `react_dev`                     |
| `https://nextjs.org/docs/app` | `nextjs_org_docs_app`           |
| `https://Supabase.com/Docs/`  | `supabase_com_docs`（小文字化） |

## 3. DTOスキーマ

[出典: 05_データ構造設計、06_処理シーケンス 1節（04→05読み替え）]

> **重要な注意**：「04*モジュール設計」と「05*データ構造設計」の間にはDTO命名・構造の不整合がある。プロジェクトでは**05を正**とする。04自体は修正されていないため、実装時は「04のクラス・メソッド構成（責務分担）はそのまま採用しつつ、DTOのフィールド構成は05および06\_処理シーケンス1節の定義に従う」という読み替えが必要。

### manifest.json（差分更新管理専用。ビルドには使わない）

```json
{
  "version": "1",
  "pages": {
    "<normalized_url>": {
      "page_hash": "sha256_of_normalized_url",
      "etag": "\"abc123\"",
      "last_modified": "Tue, 01 Jul 2026 00:00:00 GMT",
      "sitemap_lastmod": "2026-06-30T12:00:00+09:00",
      "content_sha256": "sha256_of_body",
      "last_crawled": "2026-06-30T21:30:45+09:00",
      "crawl_result": "SUCCESS"
    }
  }
}
```

```python
@dataclass(frozen=True)
class ManifestRecord:
    page_hash: str
    etag: Optional[str]
    last_modified: Optional[str]
    sitemap_lastmod: Optional[str]
    content_sha256: Optional[str]
    last_crawled: datetime          # ISO8601 タイムゾーン付き
    crawl_result: CrawlResult
```

**マージ更新ルール**：

| crawl_result                                                       | 更新する項目                                     | 保持する項目                                                              |
| ------------------------------------------------------------------ | ------------------------------------------------ | ------------------------------------------------------------------------- |
| `SUCCESS`                                                          | 全フィールド                                     | —                                                                         |
| `NETWORK_ERROR` / `TIMEOUT` / `SERVER_ERROR` / `TOO_MANY_REQUESTS` | `last_crawled`, `crawl_result`                   | `page_hash`, `etag`, `last_modified`, `sitemap_lastmod`, `content_sha256` |
| `NOT_FOUND` / `ROBOTS_DENIED`                                      | `last_crawled`, `crawl_result`                   | 同上                                                                      |
| `NOT_MODIFIED`                                                     | 書き込みなし（前回`SUCCESS`のまま保持）          | —                                                                         |
| 既存レコードなし（新規）                                           | crawl_result種別に関わらず全フィールドで新規登録 | —                                                                         |

`duplicate`（重複判定）は保持しない。Builderがビルドのたびに毎回全件照合する。

### CrawlResult（列挙型）

```python
class CrawlResult(str, Enum):
    SUCCESS            = "SUCCESS"
    NOT_MODIFIED        = "NOT_MODIFIED"
    NOT_FOUND           = "NOT_FOUND"
    ROBOTS_DENIED       = "ROBOTS_DENIED"
    NETWORK_ERROR       = "NETWORK_ERROR"
    TIMEOUT             = "TIMEOUT"
    SERVER_ERROR        = "SERVER_ERROR"
    TOO_MANY_REQUESTS   = "TOO_MANY_REQUESTS"
```

| 値                  | 説明                  |
| ------------------- | --------------------- |
| `SUCCESS`           | 200 OK                |
| `NOT_MODIFIED`      | 304。manifest更新なし |
| `NOT_FOUND`         | 404                   |
| `ROBOTS_DENIED`     | robots.txtで禁止      |
| `NETWORK_ERROR`     | 接続・DNSエラー       |
| `TIMEOUT`           | タイムアウト          |
| `SERVER_ERROR`      | 5xx                   |
| `TOO_MANY_REQUESTS` | 429                   |

**削除・404ページの扱い**：sitemap・クロール双方から発見されなくなったURLはmanifestから**削除**（要件23節）。引き続き発見されるが404/ROBOTS_DENIEDを返すURLは**保持**し次回も再試行。

## 5. CLI・環境変数 早見表

[出典: 07_CLI仕様]

### CLI引数

| 引数                  | 必須 | 説明                                                                      |
| --------------------- | ---- | ------------------------------------------------------------------------- |
| `url`（位置引数）     | 任意 | 単一サイト処理時の対象URL。省略時は`.env`の`BASE_URLS`                    |
| `--manifest <path>`   | 任意 | manifest.json保存先を上書き（単一サイト処理時のみ／複数サイト時はエラー） |
| `--log-level <LEVEL>` | 任意 | `LOG_LEVEL`の一時上書き（`DEBUG`/`INFO`/`WARNING`/`ERROR`）               |
| `--help` / `-h`       | -    | ヘルプ表示、終了コード0                                                   |
| `--version`           | -    | バージョン表示、終了コード0                                               |

設定優先順位：`CLI引数 > .env（環境変数） > デフォルト値`

### 環境変数（`.env`）

| 変数名            | 説明                                                | デフォルト               | 未定義時                                                   |
| ----------------- | --------------------------------------------------- | ------------------------ | ---------------------------------------------------------- |
| `BASE_URLS`       | 複数サイトURL（改行区切り）                         | なし                     | CLI指定があればスキップ、両方未指定はConfigError           |
| `MODE`            | `incremental` / `full`                              | `incremental`            | デフォルト適用                                             |
| `WORD_LIMIT`      | 結合Markdown1ファイルあたりの語数上限               | `450000`                 | デフォルト適用                                             |
| `REQUEST_DELAY`   | リクエスト間の待機秒数                              | `0.5`                    | デフォルト適用                                             |
| `USER_AGENT`      | HTTPアクセス時のUser-Agent                          | `NotebookLM-Crawler/1.0` | デフォルト適用                                             |
| `INCLUDE`         | 取得対象パス                                        | なし                     | 未設定時は対象URLのパス部分を暗黙INCLUDEとして適用（後述） |
| `EXCLUDE`         | 除外対象パス                                        | なし                     | デフォルト適用（制限なし）                                 |
| `MAX_PAGES`       | フォールバッククロール時上限（sitemap時は警告閾値） | `1000`                   | **ConfigError**                                            |
| `TIMEOUT_SECONDS` | HTTPタイムアウト秒数                                | `30`                     | **ConfigError**                                            |
| `LOG_LEVEL`       | `DEBUG`/`INFO`/`WARNING`/`ERROR`                    | `INFO`                   | デフォルト適用                                             |
| `LOG_FORMAT`      | `text` / `json`                                     | `text`                   | デフォルト適用                                             |
| `LOG_FILE_PATH`   | ログファイル出力先                                  | `logs/crawler.log`       | デフォルト適用                                             |

> `BASE_URL`（単数）は`.env`では使用しない。単一サイト指定はCLI引数のみ。

### 暗黙INCLUDE（v1.0.1 Issue #6対応）

`INCLUDE`未設定時、対象URLがドメインルート以外のパスを含む場合、そのパス部分を暗黙のINCLUDEとして自動適用する。sitemap利用時のクロールは常にドメインルートの`sitemap.xml`を参照するため、この対応がないと指定パス外（`/blog/`等）まで取得対象になってしまう不具合があった。`INCLUDE`明示指定時は常にそちらが優先される。削除ページ判定（`_apply_deletion_guard`）の比較範囲も同じスコープに統一。

### 終了コード

| コード | 意味                   | 発生条件                                         |
| ------ | ---------------------- | ------------------------------------------------ |
| `0`    | 正常終了               | 全サイト完了、致命的エラー・サイト単位の失敗なし |
| `1`    | 致命的エラー（未実行） | `ConfigError`等でジョブが開始できなかった        |
| `2`    | 部分的失敗             | 1つ以上のサイトで致命的なサイト単位エラー発生    |

ページ単位のエラー（`NOT_FOUND`/`NETWORK_ERROR`/`TIMEOUT`/`SERVER_ERROR`/`TOO_MANY_REQUESTS`/`ROBOTS_DENIED`）は想定内挙動であり、単体では終了コード2にしない。

### 差分判定の優先順位（要件20節）

1. sitemapの`lastmod`比較（一致すればHTTPリクエスト自体を省略）
2. HTTP条件付きリクエスト（`If-Modified-Since`/`If-None-Match`）
3. 本文SHA256比較

### 重複除去ルール（要件18節）

- 対象は200 OKで取得できたページのみ（304は対象外）
- 判定：本文SHA256一致
- 重複時は**後から見つかったURLを優先**して残す
- 除外されたページは`manifest.json`には記録として残すが、結合Markdown・`chunk_manifest.json`・`Index.md`からは除外
- 再結合はビルドが毎回キャッシュ全件から再構築されるため自動的にトリガーされる
