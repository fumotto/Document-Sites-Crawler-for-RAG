# 03_ディレクトリ構成

## 設計方針

- 責務ごとにトップレベルディレクトリを分離する。（キャッシュ・成果物・アーカイブ・ログの責務を明確にするため）
- Pythonソースコードは `src/app/` 配下にパッケージ構成で配置する。（保守性・拡張性・テスト容易性を高めるため）
- DTOは `models/` パッケージ配下へ責務単位で配置する。（1ファイル1クラスを原則とし、関連するDTOを同一責務で整理するため）
- サイトごとのデータはサイト識別子単位で完全に分離する。（複数サイト処理時の独立性を確保するため）
- サイト識別子はURLから機械的に生成する。（人間が判読でき、再現可能な命名規則とするため）
- キャッシュ内ではMarkdown本文とメタデータを分離管理する。（可読性・処理効率を向上させるため。具体的な役割分担は「05_データ構造設計」で定義する）
- `output/` には最新成果物を保持する。（NotebookLM投入前確認を容易にするため）
- `archives/` にはZIP成果物を世代管理する。（履歴管理を容易にするため）
- ログは `crawler.log` に追記（Append）する。（実行履歴を保持するため）
- `tests/` ディレクトリを標準構成に含める。（テスト追加を容易にするため）
- 本成果物ではディレクトリ構成のみを定義し、`src/app/` 配下の詳細構成は「04_モジュール設計」に委ねる。（成果物間の責務を明確にするため）
- キャッシュ内ファイル（`pages/` / `metadata/`）の具体的なスキーマおよび `{page_hash}` の算出方法は、本成果物では確定せず「05_データ構造設計」で正式に定義する。（成果物間の責務を明確にするため）

## サイト識別子

### 命名ルール

URLから以下の手順で生成する。

1. スキーム（`https://` 等）を除去する。
2. ホスト名およびパスを含め、**すべて小文字化する**。
3. 英数字以外の文字（`/` `.` `:` `-` 等）は `_` に置換する。
4. `_` が連続する場合は1文字へ圧縮する。
5. 先頭・末尾の `_` は除去する。
6. 生成結果をサイト識別子として採用する。

> v1からの変更点：手順2（小文字化）を追加した。クロール時のURL正規化ルール（要件定義書 7節）における「スキーム・ホスト名を小文字化する」という方針と一貫性を持たせるため、サイト識別子の生成においても大文字・小文字表記の揺れによる識別子の不一致を防止する。

### 末尾スラッシュの扱い

`https://example.com/docs/` と `https://example.com/docs` は、本ルールを適用するといずれも `example_com_docs` となり、サイト識別子が一致する。

**この一致は仕様とし、識別子の衝突としては扱わない。** 末尾スラッシュの有無のみが異なるURLは同一サイトとみなし、同一の `{site_identifier}` 配下でキャッシュ・成果物・アーカイブを共有する。

### 例

| URL | サイト識別子 |
|---|---|
| `https://supabase.com/docs/` | `supabase_com_docs` |
| `https://react.dev` | `react_dev` |
| `https://nextjs.org/docs/app` | `nextjs_org_docs_app` |
| `https://Supabase.com/Docs/` | `supabase_com_docs`（小文字化により上記と一致） |

## ディレクトリ責務

| ディレクトリ | 責務 |
|---|---|
| `src` | アプリケーションソースコード |
| `cache` | 差分更新に利用する永続キャッシュ |
| `output` | 最新成果物 |
| `archives` | ZIP成果物の履歴保存 |
| `logs` | ログ出力 |
| `tests` | テストコード |

## 補足

- `src/app/` 配下のパッケージ構成および各モジュールの責務は、「04_モジュール設計」で定義する。
- `cache/` 配下の `pages/` と `metadata/` は同一ハッシュ名（`{page_hash}`）で対応付ける。両者の役割分担、および `manifest.json` との関係は「05_データ構造設計」で正式に定義する。
- `{page_hash}` の算出元（URLベース／本文SHA256ベース）は本成果物では確定しない。「05_データ構造設計」で正式に定義する。
- `output/` の内容はZIP生成後も保持し、NotebookLMへのアップロードや成果物確認に利用する。
- `archives/` は世代管理専用ディレクトリとし、ZIPファイルは上書きしない。
- パス長について：現時点ではサイト識別子・ハッシュ値ともに現実的な長さであり、Windows環境のパス長制限（260文字）に抵触する可能性は低いと判断し、追加の短縮処理（識別子の最大長制限等）は行わない。ただし、今後実運用において問題が確認された場合に対応できるよう、サイト識別子・ハッシュ生成ロジックは変更が容易な構造で実装する。
