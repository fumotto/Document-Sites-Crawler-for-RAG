# 結合テスト（シナリオテスト）ケース一覧表

## 凡例
- **テスト優先度**：最高／高／中／低（単体テストと同一基準）
- **テストメソッド名**：現時点で未作成のため全欄空欄
- 区分A：Docker Composeコマンドからの起動テスト（CLI/Docker版のシナリオテスト）
- 区分B：Playwright を用いたE2Eテスト（デスクトップアプリGUI版のシナリオテスト。PyWebViewの`web/index.html`をブラウザ経由で操作する想定）

### 補足・実施上の留意点

- **テスト用Webサーバ**：実サイトへの外部通信を避けるため、モックHTTPサーバ（sitemap.xml・robots.txt・複数ページ・404/429/5xx応答・ETag対応などを切り替えられるもの）をテスト環境内に用意することを推奨します。DC系・E2E系の多くがこのモックサーバに依存します。
- **A区分とB区分の役割分担**：クロール・ビルド・アーカイブのロジック的な網羅性（sitemap有無、差分判定、重複除去、削除判定等）はA区分（Docker Compose起動）で担保し、B区分（Playwright）は画面遷移・表示内容・ユーザー操作性に焦点を当てています。ロジックの重複検証は避け、E2Eは「バックエンドが正しく動くことを前提に、UIが正しくそれを伝えているか」を主眼にしています。
- **DC-024（Resumeテスト）・E2E-020（クローズ確認ダイアログ）** はタイミング制御が難しく実装コストが高いため、優先度は中〜高に留めていますが、自動化が困難な場合は手動テスト運用も検討してください。
- 本表は「CI・Dockerfile・インストーラ関連」（`.github/workflows/*`、`Dockerfile`、`main.spec`、`installer.iss`等）を対象外としています。
