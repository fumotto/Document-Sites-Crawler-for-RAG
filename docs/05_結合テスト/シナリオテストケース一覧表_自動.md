# シナリオテストケース一覧表_playwrite

本表は結合テスト（シナリオテスト）のうち、自動テストとして実装する範囲を対象とする。

- 区分A：Docker Composeコマンドからの起動テスト（`tests/integration/docker/`）
- 区分B：Playwright を用いたE2Eテスト（`tests/integration/e2e/`、`pywebview.api` をJSスタブ化しUIロジックのみ検証）

CI・Dockerfile・インストーラ関連は対象外とする。

DC-024（Resumeテスト）・E2E-020（クローズ確認ダイアログ）は、テストコードの安定性を優先し自動テスト対象から除外し、「シナリオテストケース一覧表_手動.md」に手動確認項目として記載する。

## 凡例
- **テスト優先度**：最高／高／中／低（単体テストと同一基準）
- **テストメソッド名**：未作成のため全欄空欄

## B. Playwright を用いたE2Eテスト（デスクトップアプリGUI版）

前提：`web/index.html`をPlaywrightのブラウザコンテキストで開く際、`fixtures/pywebview-stub.ts`を`addInitScript`等で注入し、`window.pywebview.api`の各メソッド（`get_app_info` / `load_settings` / `start_execution` / `get_status` / `open_log_folder`）をシナリオ別にあらかじめ定義した固定応答・状態遷移で返す。実際のPython/クロール処理・`testserver/`へのアクセスは発生しない。

### 補足・実装上の留意点

- `testserver/`のシナリオ切り替え方式：DC-020やDC-022のように「1回目実行後にサーバ側の応答を変更する」ケースがあるため、`testserver/server.js`に簡単な管理エンドポイント（例：`POST /__scenario__`でシナリオ名を切り替える）を用意しておくと、テストコードから状態を制御しやすくなる。
- DC-024・E2E-020は本表から除外し、手動確認項目として「シナリオテストケース一覧表_手動.md」に記載する。
