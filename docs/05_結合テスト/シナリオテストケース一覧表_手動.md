# シナリオテストケース一覧表_手動

本表は、「シナリオテストケース一覧表_自動.md」で自動テスト対象から除外したテストケースを、手動確認項目として記載したものである。

除外理由は共通して「テストコードの安定性を優先するため」であり、自動化した場合にタイミング制御の難しさや実行環境依存によりテストが不安定になるリスクが高いと判断したものである。

## 凡例

- **テスト優先度**：最高／高／中／低（単体テスト・自動結合テストと同一基準）
- **確認頻度目安**：リリース前など、実施すべきタイミングの目安

## 自動化から除外した理由

### DC-024（Resumeテスト）

- プロセスkillは「クロールが何件処理されたタイミングで発火させるか」の制御が難しく、CI環境やローカル環境の実行速度差によってタイミングがずれるとテストの再現性が損なわれる。
- `testserver`側で「N件応答後に遅延を入れる」といった仕組みを用意すれば自動化の余地はあるが、実装・保守コストに対して得られる検証価値（レジューム機能自体は`manifest.json`のアトミック書き込み・マージ更新ルールの単体テストである程度担保されている）を鑑み、現時点では手動確認とする。
- 将来的に自動化する場合は、`tests/integration/testserver/scenarios/` に遅延応答シナリオを追加し、`tests/integration/docker/test_docker_scenarios.py` から `docker compose kill` を発火するタイミング制御を実装することを検討する。

### E2E-020（クローズ確認ダイアログ）

- 当該機能（`window.events.closing` によるクローズ時のconfirmダイアログ表示）はPyWebView固有のイベント機構に依存しており、`main.js`側の`onClosing`相当のロジックはPython側（`desktop_main.py`）に実装されている。
- Playwrightで開く`web/index.html`は素のブラウザコンテキストであり、`window.pywebview`のクローズイベント自体をスタブで模倣しても、実際のOSネイティブウィンドウの挙動（×ボタン押下→confirm→キャンセル/OK）とは異なる検証になってしまい、テストとしての意味が薄れる。
- そのため、本機能はビルド済みデスクトップアプリ（または開発環境での起動）を用いた手動確認に委ねる。

## 手動確認の実施タイミング（推奨）

| タイミング | 実施項目 |
|---|---|
| リリース前（バージョンタグpush前） | DC-024・E2E-020の両方を実施する |
| `site_lock.py` / `manifest_repository.py` / `directory_bootstrap.py` に変更が入った場合 | DC-024を実施する |
| `desktop_main.py` / `main.js`（画面遷移・イベントハンドリング部分）に変更が入った場合 | E2E-020を実施する |

### 補足

- 本表に記載の2件以外にも、自動化が困難と判明した項目が今後発生した場合は、本表へ追記していく運用とする。
- 手動確認の実施結果（実施日・実施者・結果）は、別途リリースチェックリスト等での記録を推奨する。本表自体には実施履歴は含めない。
